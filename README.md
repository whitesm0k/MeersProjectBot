# MeersProject Secure Bot

Новый модульный Discord-бот: безопасность сервера + тикеты + вакансии + отчёты + верификация.

## Состав

- `bot.py` — запуск, intents, загрузка модулей, обработка событий.
- `config.py` — настройки из `.env`.
- `cogs/tickets.py` — обычные тикеты и покупочные уведомления.
- `cogs/vacancies.py` — заявки Media/Support и открытие/закрытие набора.
- `cogs/reports.py` — форма отчёта, приватные ветки, проверка администратором.
- `cogs/verification.py` — панель Verification.
- `security/antispam.py` — антиспам и тайм-аут.
- `security/audit_guard.py` — обнаружение массовых входов, создания каналов/ролей и вебхуков через audit log.
- `services/` — права, логи, модерация, JSON-хранилище.
- `data/` — создаваемые ботом настройки состояния.

## Установка на Windows

1. Распакуйте архив в отдельную папку.
2. Откройте терминал в папке проекта.
3. Создайте окружение:
   ```powershell
   py -m venv .venv
   .venv\Scripts\activate
   ```
4. Установите библиотеки:
   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
5. Скопируйте `.env.example` в `.env`.
6. Заполните `.env` реальными значениями и ID.
7. Запустите:
   ```powershell
   python bot.py
   ```

## Slash-команды

- `/setup_tickets` — панель обычных тикетов.
- `/setup_vacancies` — панель вакансий.
- `/openvacmed`, `/closevacmed` — набор Media.
- `/openvacsupp`, `/closevacsupp` — набор Support.
- `/setup_report` — панель подачи отчётов.
- `/setup_verification` — панель верификации.

Команды доступны администраторам сервера, пользователям из `ADMIN_IDS` и участникам с настроенной админской ролью (где применимо).

## Порядок закрытия тикетов и заявок

1. Саппорт/администратор нажимает «Взять в работу».
2. Бот записывает ID сотрудника в тему канала.
3. Только этот сотрудник может нажать «Закрыть тикет».
4. Назначение сохраняется после перезапуска.

Одинаковый механизм применяется к обычным тикетам и вакансиям.

## Права и intents в Discord Developer Portal

Включите:
- Server Members Intent
- Message Content Intent

Выдайте боту:
- View Channels, Send Messages, Read Message History
- Manage Channels
- Manage Roles (для верификации)
- Moderate Members (для тайм-аутов)
- View Audit Log (для анти-рейда)
- Manage Webhooks (только если планируете вручную удалять вебхуки)
- Create Private Threads, Send Messages in Threads, Manage Threads
- Use Application Commands, Embed Links, Attach Files

Роль бота должна быть выше ролей, которые он выдаёт/снимает, и выше ролей пользователей, которым он выдаёт тайм-аут.

## Защита от рейдов

По умолчанию массовый вход и подозрительное создание объектов только логируются. Это сделано намеренно: один всплеск входов или действий не доказывает атаку, поэтому бот не банит участников автоматически.

`AUTO_REVERT_RAID_ACTIONS=false` — рекомендуемое значение. При `true` бот может удалять канал/роль, созданные участником после превышения лимита, и выдавать тайм-аут. Включайте только после тестирования и осознанной настройки порогов.

Создание вебхуков обнаруживается через Discord audit log при событии обновления вебхуков; постоянного опроса API каждые 2 секунды нет.

## Важно о токене

Не присылайте `.env` и токен в чат, не добавляйте `.env` в архив или Git. Если токен ранее публиковался или передавался третьим лицам, сбросьте его в Discord Developer Portal и используйте новый.


## Welcome / Invite greeting

Добавлен функционал из предоставленного Invite Bot:
- приветствие новых участников в `WELCOME_CHANNEL_ID`;
- картинка с круглым аватаром на исходном фоне `assets/welcome_background.png`;
- автоматическая выдача `ROLE_UNVERIFIED_ID` каждому новому участнику;
- дополнительная автоматическая выдача `WELCOME_ROLE_ID` (если задана);
- переключатель отображения количества участников;
- текст приветствия с плейсхолдерами `{user}` и `{count}`;
- команда `/welcome_test` для проверки приветствия администратором.

Генерация картинки выполняется внутри основного бота через Pillow:
отдельный FastAPI/uvicorn процесс и HTTP API больше не нужны. Если генерация
картинки не сработает, бот всё равно отправит текстовое приветствие. Выдача
роли не зависит от наличия или доступности приветственного канала.

Добавьте в `.env`:
```env
WELCOME_CHANNEL_ID=ID_КАНАЛА
WELCOME_ROLE_ID=ID_ДОПОЛНИТЕЛЬНОЙ_РОЛИ
ROLE_UNVERIFIED_ID=ID_РОЛИ_UNVERIFIED
SHOW_MEMBER_COUNT=true
WELCOME_MESSAGE="{user} — Новый пользователь!\\n\\n**{count}** Число пользователей сервера."
```

Включите **Server Members Intent** в Discord Developer Portal и выдайте
боту права **View Channel**, **Send Messages**, **Attach Files**, **Manage Roles**
(если используется автоматическая роль). Роль бота должна располагаться выше
выдаваемой роли. Старый токен из Invite Bot не переносился.


### Роль Unverified при входе

`ROLE_UNVERIFIED_ID` — обязательная настройка для автоматической выдачи роли
Unverified при каждом входе нового участника. Укажите ID существующей роли
в `.env`. Бот должен иметь право **Manage Roles**, а его собственная роль
должна находиться выше роли Unverified. Если `WELCOME_ROLE_ID` тоже задан,
бот выдаст обе роли. Ошибка выдачи одной роли не мешает попытке выдать другую.


## Панель сотрудничества и подписки

- `/setup_partnership` — публикует панель подачи заявок на сотрудничество. Перед заполнением формы пользователь подтверждает ознакомление с правилами.
- `PARTNERSHIP_CATEGORY_NAME` — необязательное имя категории приватных заявок.
- `PARTNERSHIP_RULES_URL` — необязательная ссылка на полную редакцию правил. Встроенные правила отображаются всегда.
- В тикетах с темой «Покупка» автоматически появляется постоянное меню выбора срока подписки; ссылки FunPay отправляются непосредственно в тикет.
- Система отзывов отключена и удалена из проекта. Ранее опубликованные сообщения с панелями отзывов необходимо удалить на сервере вручную.
